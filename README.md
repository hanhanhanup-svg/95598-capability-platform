# 95598 岗位能力图谱原型 · 附件参考版

本次按2026-09-08提供的附件优化基础数据，技术架构与六个主入口保持不变。采用三个岗位序列、30个参考岗位名称、七个能力族、22项能力和六类知识。详见 [附件参考版更新说明](CHANGELOG-REFERENCE.md)。

此前 V3 已将 13 个入口收敛为 6 个，并统一培养计划、待办与办理上下文。新增组织能力矩阵、同口径历史对照、协同责任标准和模板批量维护。完整说明与演示步骤见 [V3 更新说明](CHANGELOG-V3.md)。以下 V2 功能继续保留在相应二级页面。

本原型以岗位能力墙为核心，将业务体系、能力标准、人员记录和数据治理连接为可横向复用、纵向追溯的体系。

## 体验路径

- 体系全景：从岗位查看业务、能力和数据关联；支持矩阵、横向协同、纵向追溯。
- 图谱探索：选择岗位或业务场景，缩放、搜索节点，查看任务—能力—等级—行为—证据链。
- 岗位能力墙：查看岗位人员、成长目标、证据覆盖，点击姓名打开能力画像和证据，导出当前筛选结果。
- 业务架构：浏览3个业务域、8个场景、24项任务及22项能力标准。
- 数据治理：目录、血缘、标准、标签、质量和业务映射六个视图相互关联。
- 培养发展：个人成长、导师带教与人才梯队共用计划；训练与实践后建立真实的模拟评价草稿，复核生效后回流能力墙。

建议先查看许澄的信息核查已满足、依据解释需提升、AI结果校验待验证，再体验林悦的疑难处置差距，再查看周宁的证据缺口、顾言的过期证据、沈薇的待复核记录。

## 数据与状态

40名人员、6个履职样本、390条能力对标要求、42条证据、12条知识示例和6项数据资产为合成演示。三个序列的30个岗位名称参考修订稿正文，其中25个岗位名称暂未建立完整能力标准。原始附件未提供这些具体人员及评分阈值。

等级只用于“当前等级是否达到要求”的比较，不换算能力分数。能力墙展示已达标、未达标、待补证和适用项；已确认达标项占比为达标项数/适用项数。缺证、过期和待复核不当零分，必选门槛不能被其他能力抵消。可选择统一星级对标或个人成长目标。训练完成、任职和场景授权分别办理，不自动升星。

组织任职、版本草稿、模拟审批、评价、供需安排与培养计划保存于当前浏览器的本地演示记录，刷新后继续。数据是设备与浏览器独立的，不提供多用户协同或生产权限。没有真实数据接入或正式人事评价系统。

## 本地运行

需要 Node.js 22.13 或更高版本。

```text
npm ci
npm run dev
```

浏览器访问启动信息中显示的本机地址。生产输出：

```text
npm run build
npm start
```

静态部署目录为 `dist/client`，无需数据库、密钥或后台接口。Sites 注册信息在 `.openai/hosting.json`。Windows 构建入口使用自然退出方式，避免上游 CLI 立即退出时的原生句柄关闭异常；非零退出和构建错误保持原样。

## 文件与扩展

- `app/mock-catalog.json`：统一模拟目录、岗位、任务、能力、人员、证据和资源。
- `app/model.ts`：引用查询、分类型差距和指标计算。
- `app/*-view.tsx`：业务视图；`detail-panel.tsx` 为上下游追溯详情。
- `app/platform.css`、`app/extras.css`：国网绿视觉和响应式样式。

通过稳定编码连接实体，新增岗位需要补齐岗位职责、场景任务以及独立的岗位星级能力要求；新增能力需要等级、行为标准、证据用途和成长资源。所有标准进入正式评价前应经人工确认。

## V2 新增管理功能

1. 组织与岗位：组织层级、岗位序列、编制调整、主岗/兼岗/支援、有效任职与历史记录。
2. 体系与版本：对象定义、关系复用、分级行为标准、场景规则、差异与影响清单、结构校验、审核发布及历史快照。新增岗位能力引用时明确确认一至五星要求。
3. 场景上岗授权：按能力、证据、有效任职及授权分别核验，支持申请、审批、指导人、有效期与暂停。续期申请不会替代当前有效授权。
4. 评价与复核：独立事件去重、有效期/质量/冲突检查、证据排除依据、采信与复核、员工异议和结果历史。已生效结果冻结证据快照。
5. 组织能力供需：按场景、班组、小时段计算需求与实际供给，人员在同一时段只有一个服务岗位；支援预案显示目标与原场景缺口。
6. 业务结果诊断：透明的分子分母、同口径样本和主因分类；整改责任、期限、产出、验收与后续业务观察。异常不直接扣减人员能力。
7. 人才梯队：专业/管理通道、发展意愿、导师、周期、必需实践、目标复测和后备候选确认；培养中人数不计入当前独立供给。

## 建议演示路径

- 在组织与岗位中查看陈序的报修主岗与投诉兼岗，中心仍是40名独立人员。
- 在能力供需与预警中将陈序从报修支援至投诉：投诉由4/5变为5/5，报修由6/6变为5/6，另一个小时段不变。
- 在体系与版本中新建草稿，调整故障场景门槛或行为描述，查看影响清单后提交、复核、发布。行为变化需按新标准重新复核旧证据适用性。
- 评价与复核中选择林悦：对原L2观察记录排除依据，补充两个不同事件编码的L3实操观察，提交评价并由另一复核人确认。原星级不变，能力墙更新单项结果。
- 在业务结果诊断中分别安排知识、流程或行为核验事项，提交产出并完成验收。
- 在人才梯队中查看顾清的高级故障研判培养路径，提交实践记录和目标复测。季宁仍是当前唯一符合高级条件的人员，后备不提前计入供给。

所有需求、阈值、行为、人员、导师、业务事件、审批身份和指标均为合成演示，不代表实际国网制度或人员结论。
